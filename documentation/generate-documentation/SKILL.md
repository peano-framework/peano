# Regenerate Doxygen Documentation

Peano's HTML API documentation is generated by Doxygen from `documentation/Doxyfile`
(see the "Documentation" section of `CLAUDE.md`). It scans `src`, `python`, `tutorials`,
`benchmarks`, `tests`, `applications`, `spack`, `docker`, `apptainer` and `documentation/`
and writes HTML to `doxygen-html/html` (gitignored). Several `.dox` files are generated
from Jupyter notebooks (`.ipynb`), so every rebuild first regenerates those.

Both steps live in one script, `.claude/skills/regen-docs/regen-docs.sh`, which this
skill and the automatic `PostToolUse` hook share.

## Steps

1. Run the script for the repository (or git worktree) whose documentation you want:
   ```sh
   .claude/skills/regen-docs/regen-docs.sh [repository-root]
   ```
   Without an argument it uses the git top level of the current directory. It runs
   `python3 documentation/convert-jupyter-notebooks.py` (about 45 s) and then
   `doxygen documentation/Doxyfile` (about 9 min) from that root. Run it in the
   background (Bash `run_in_background`) and wait for its completion notification.
   If a rebuild for the same root is already running (e.g. started by the hook), the
   script skips and says so - then wait for that run instead.
2. Output of both steps goes to `<root>/.doxygen-rebuild.log`; the last line reports
   Doxygen's exit code. Doxygen does not fail on warnings. Report warnings/errors about
   the files the user was just working on; the large pool of unrelated pre-existing
   warnings is expected.
3. Confirm `<root>/doxygen-html/html/index.html` was updated and tell the user.
4. Check if Firefox (or another browser) are already running and show the documentation.
   If not, invoke them on the `<root>/doxygen-html/html/index.html` file.

## Automatic rebuilds

`.claude/settings.json` calls `regen-docs.sh --hook` asynchronously after every
`Write|Edit|MultiEdit`. In hook mode the script reads the hook's JSON from stdin, ignores
files that are not documentation-relevant (by extension, and by directory relative to the
repository root), determines the repository or worktree holding the edited file, and
rebuilds there. Edits in worktrees under `.claude/worktrees/` hence rebuild that
worktree's `doxygen-html`, not the main checkout's.

After every `Bash` call, `regen-docs.sh --hook-bash` covers changes made via the shell
(sed, generator scripts, git mv, git merge, fast-forwarding a branch): it rebuilds the
repository or worktree of the command's working directory if any documentation-relevant
file there is newer than `<root>/doxygen-html/.rebuild-stamp`, which every rebuild
touches after the notebook conversion (whose `.dox` output would otherwise trigger the
next rebuild) and before Doxygen starts. Generated files in benchmarks or tests hence trigger a rebuild,
too.

Limitations: a `flock` on `<root>/.doxygen-rebuild.lock` skips a rebuild while another
one for the same root is running, so an edit landing during a rebuild is only picked up
by the next rebuild (for Bash changes: by the next Bash call after it finished). A Bash
command that changes files in a different repository or worktree than its working
directory is not detected - invoke this skill explicitly afterwards.
